# NRC ADAMS 문서 분석

NRC 공개 문서 검색, 원문 PDF 확인, 영어·한국어 요약과 맞춤 추출, 근거를 포함한 선택 저장을 지원합니다. 각 계정이 본인의 NRC APS 키와 Gemini·OpenAI·Claude API 키를 등록합니다.

## 로컬 실행

Windows에서는 **NRC ADAMS 실행** 바로가기 또는 이 폴더의 `launch.cmd`를 더블클릭하면 서버가 시작되고 기본 브라우저가 열립니다. 서버가 이미 실행 중이면 브라우저만 엽니다. 바로가기를 다시 열어도 키와 작업 기록은 유지됩니다. 실행 오류는 이 폴더의 `.data/launcher.log`를 확인하세요. Node.js 24 이상이 필요하며 npm 패키지는 설치할 필요가 없습니다. 터미널에서도 실행할 수 있습니다.

```powershell
npm.cmd start
```

브라우저에서 [로컬 앱](http://127.0.0.1:4317)을 열고 **계정 만들기**를 선택합니다. 12자 이상 비밀번호를 설정하고 **API 설정**에 사용할 AI 키를 저장합니다. NRC 키를 추가하면 앱 안에서 NRC 검색 결과와 메타데이터를 조회할 수 있습니다. **연결 확인**으로 키와 모델 접근을 확인할 수 있습니다. AI 연결 확인은 짧은 API 요청을 1회 실행합니다.

문서 검색에서 `ML24017A120`을 입력해 검색한 다음 제목을 눌러 **한영 요약**을 선택하세요. **맞춤 추출**에 필요한 항목을 입력하고 결과에서 저장할 행을 선택합니다. **보관함**에서 결과를 다시 열고 CSV로 내보낼 수 있습니다.

문서를 열면 원문 PDF의 첫 페이지가 자동으로 표시됩니다. 상세 분석을 이어가려면 **원문 PDF 내려받기**를 누르고 **Gemini Notebook에서 상세 분석**을 열어 내려받은 파일을 노트북 소스로 추가하세요. [Gemini Notebook](https://notebook.google.com/) · [PDF 소스 추가 안내](https://support.google.com/gemininotebook/answer/16215270?hl=ko)

## 문맥으로 문서 검색

**AI로 검색 의도 분석**이 켜져 있으면 검색 버튼이 한국어·영어 설명을 분석하고 NRC 용어와 문서 유형을 고려한 영어 검색식을 최대 세 개 만듭니다. 예를 들어 “2022년 이후 Palo Verde 2호기 인허가 변경을 승인한 NRC 문서”에서 승인 근거를 다루는 Safety Evaluation과 발급된 License Amendment를 구분해 찾습니다. 앱은 고급 필터를 보존하고, 인식할 수 있는 작성일 표현을 날짜 조건으로 반영합니다. 여러 검색식에 함께 나온 문서를 우선 표시하고 ML 번호로 중복을 제거합니다. 결과의 **AI가 파악한 검색 의도**에서 사용한 검색식을 볼 수 있습니다.

ML 번호만 입력하면 해당 문서를 바로 확인합니다. 검색 결과에 원문 주소가 비어 있으면 문서를 열 때 ML 번호로 공개 PDF를 찾습니다. 입력한 검색어 그대로 찾으려면 **AI로 검색 의도 분석**을 끄세요. Gemini가 일시적인 503을 반환하면 남은 제한 시간과 서버의 대기 지시를 확인해 최대 한 번 재시도합니다. 계속 실패하면 원래 검색어와 적용한 날짜 조건으로 검색하고 이유를 표시합니다.

## NRC API 키 없이 사용하기

1. **문서 검색 → NRC 키 없이 공개 경로 사용**을 선택합니다. NRC 키가 없는 계정은 이 경로가 기본으로 선택됩니다.
2. ML 번호를 알고 있으면 검색창에 넣습니다. 앱이 NRC의 공개 문서 경로에서 PDF를 확인합니다. 설명으로 찾을 때는 앱이 만든 검색식을 눌러 제목·유형·작성일 등 필터가 반영된 공식 공개 검색 결과를 엽니다. AI 검색을 끈 경우 **NRC 공개 검색 결과 열기**를 사용합니다.
3. **공개 PDF 가져오기**에 찾은 ML 번호나 NRC 공식 PDF 주소를 붙여넣습니다. 공개 경로에서 PDF를 바로 열 수 없다면 NRC에서 파일을 내려받아 같은 화면에서 올립니다. 업로드한 PDF는 해당 계정에서만 열 수 있으며 파일당 96 MB, 계정당 총 128 MB까지 저장합니다.
4. 가져온 문서에 **한영 요약**, **맞춤 추출**, **선택 저장**을 사용합니다. AI 분석에는 설정한 Gemini·OpenAI·Claude API 키가 필요합니다.

**보관함 → 업로드한 원본 PDF 관리**에서 파일별 크기와 전체 사용량을 확인하고 원본을 삭제해 공간을 확보할 수 있습니다. 원본을 삭제해도 저장한 한영 결과와 인용은 보관됩니다. 업로드 시 입력한 ML 번호로 보관함의 저장 결과를 검색할 수 있습니다.

[NRC 공개 고급검색](https://adams-search.nrc.gov/adv-search) · [NRC 공개 문서 안내](https://www.nrc.gov/documents-reports/adams-public-documents)

## 계정과 키

- 키는 계정·제공자별로 SQLite에 AES-256-GCM 암호화 상태로 저장됩니다. 저장한 키는 화면에 다시 표시되지 않습니다. 로컬 암호화 키는 처음 실행할 때 `.data/master.key`에 생성됩니다.
- 기본 AI는 계정마다 변경할 수 있습니다. Gemini는 저장한 키로 Google의 모델 목록을 불러옵니다. 문서 분석용 후보를 선택해서 저장하고 **연결 확인**을 누르면 실제 생성 성공 여부와 응답 시간이 표시됩니다. 목록 등재와 모델별 사용 한도 또는 생성 성공은 별개입니다. OpenAI·Claude는 모델 ID를 직접 입력할 수 있습니다.
- OpenAI와 Claude는 개발자 API 키를 사용합니다. 웹 구독 플랜과 API 사용은 제공자별로 별도 관리됩니다. 사용자가 선택한 제공자에게 공개 PDF와 질문이 전달되며 API 사용량은 해당 사용자의 키에 기록됩니다.

[NRC APS 키](https://adams-api-developer.nrc.gov/profile) · [Google AI Studio 키](https://aistudio.google.com/apikey) · [OpenAI API 키](https://platform.openai.com/api-keys) · [Claude API 키](https://platform.claude.com/settings/keys)

## 공유 환경

동일 서버에서 여러 사용자가 각자 계정을 사용합니다. 외부에 제공하려면 HTTPS 리버스 프록시 뒤에서 단일 Node 프로세스로 실행하고 `.data`를 영구 디스크에 둡니다. 프록시는 설정한 서비스 호스트만 받고 Node 포트는 사설 네트워크 또는 루프백에 둡니다.

- `ADAMS_ORIGIN`에 HTTPS 공개 주소를 설정합니다. 앱이 이 주소를 기준으로 교차 사이트 요청을 차단하고 보안 쿠키를 발급합니다.
- `ADAMS_MASTER_KEY`에 임의의 32바이트 키를 64자리 16진수로 저장합니다. 로컬 DB를 공유 환경으로 이동할 때는 로컬 `.data/master.key`의 원래 바이트를 16진수로 사용해야 기존 키를 읽을 수 있습니다.
- `ADAMS_INVITE_CODE`에 12자 이상의 초대 코드를 설정하고 가입할 사람에게 전달합니다. 가입 시 이메일 주소는 로그인 ID로 사용됩니다. 이메일 본인 확인과 비밀번호 재설정 메일은 현재 버전의 범위 밖입니다.
- 환경 변수는 서비스 관리자에서 주입하거나 `.env.example`을 참고해 Git에서 제외된 `.env`에 둡니다. DB와 암호화 키는 각각 접근권한을 제한하고 백업합니다.

## 문서 처리 범위

원문은 최대 96 MB까지 앱 서버에서 받습니다. 앱이 원문 페이지를 렌더링해 **PDF 미리보기**에 표시하므로 NRC의 외부 프레임 허용 여부와 브라우저 내장 PDF 뷰어 설정에 영향을 받지 않습니다. 다운로드 또는 브라우저 PDF 뷰어는 **새 탭에서 열기**를 사용하세요.

**요약**은 100쪽 또는 12 MB를 넘으면 문서 앞부분의 Executive Summary·Abstract·Overview 등을 찾아 개요만 분석합니다. 별도 개요를 찾지 못하면 앞 12쪽을 사용합니다. **맞춤 추출**은 44쪽 또는 12 MB를 넘으면 질문과 관련된 페이지를 골라 보냅니다. 텍스트로 위치를 확인하기 어려운 스캔본은 표본 페이지를 살펴봅니다. PDF 쪽수를 알고 있다면 **PDF 쪽수 지정**에 최대 36쪽을 입력할 수 있습니다. 결과에는 분석 범위와 원본 PDF 페이지 번호가 표시됩니다.

선택한 쪽의 텍스트를 온전히 담을 수 있으면 페이지 번호와 텍스트를 AI에 보냅니다. 텍스트가 잘리거나 입력 예산을 넘는 경우, 스캔본이나 표·도면을 읽는 경우에는 PDF 페이지를 보냅니다. 긴 문서의 맞춤 추출은 마지막 쪽까지 관련 위치를 찾습니다. 색인 시간이 초과되거나 위치를 찾지 못하면 문서 전체에 걸쳐 고른 표본 페이지와 쪽수를 표시합니다. 분석 중에는 PDF 다운로드, 페이지 읽기·선택, AI 응답 대기 단계와 경과 시간이 표시됩니다.

긴 문서 처리에는 Python과 `pypdfium2`, `Pillow`가 필요합니다. 이 Windows 환경에서는 Codex에 포함된 Python을 자동으로 찾습니다. 다른 서버에서는 아래 명령으로 설치한 Python을 `ADAMS_PYTHON`에 지정할 수 있습니다.

```powershell
python -m pip install -r requirements.txt
```

PDF에서 읽을 수 있는 영어 인용문은 해당 페이지 텍스트와 대조합니다. 스캔이나 복잡한 표처럼 자동 대조가 어려우면 **직접 확인 필요**로 표시합니다. 한영 제공 범위는 요약·추출·근거 번역입니다.

## 검증

```powershell
npm.cmd test
```

자동 검증은 NRC와 세 AI 제공자의 응답을 테스트용으로 대체해 API 키 격리, 요청 형식, 한영 결과 구조, 근거 검증, 선택 저장, 재로그인 후 보관함을 확인합니다. 실제 서비스 접근은 가입 후 앱의 **연결 확인**을 사용합니다.
